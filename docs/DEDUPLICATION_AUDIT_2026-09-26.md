## 반영한 방식

[다국어 E5 small](https://huggingface.co/intfloat/multilingual-e5-small)의 [ONNX 변환 모델](https://huggingface.co/Xenova/multilingual-e5-small)을 FastEmbed로 CPU에서 실행한다. 별도 유료 API 키가 필요하지 않다. 최초 모델 다운로드와 이후 로컬 캐시가 필요하다.

제목과 `제목 + 본문 앞 1,000자`를 각각 벡터로 만들고 정규화한 코사인 유사도를 비교한다. 본문이 없으면 RSS 설명을 사용하며 120자 미만이면 제목 기준만 적용한다.

| 조건 | 제거 기준 |
|---|---|
| 본문/설명 양쪽 충분 | 본문 점수 ≥ 0.93 **그리고** 제목 점수 ≥ 0.85 |
| 본문 증거가 더 강함 | 본문 점수 ≥ max(설정값, 0.96) **그리고** 제목 점수 ≥ 0.82 |
| 본문/설명 부족 | 제목 점수 ≥ 0.94 |

`DAPA_SEMANTIC_THRESHOLD`로 본문 기준을 조절할 수 있다. 점수 0.93은 **동일 기사일 확률 93%라는 뜻이 아니다.** 이번 5일 자료로 초기 보정한 값이며 모든 미래 기사의 정확도를 보장하지 않는다.

- 기존 문자 기반 검사도 함께 사용한다. 멕시코 전용 규칙은 추가하지 않았다.
- 모든 섹션에서 이미 선정한 대표 기사와 직접 비교한다. A-B, B-C가 비슷하다는 이유만으로 A-C까지 무조건 묶지 않는다.
- 체결/취소, 서로 다른 명시적 무기·수출국 충돌은 보존한다. 같은 URL은 하나의 기사로 유지한다.
- 인터뷰와 비인터뷰 제목의 의미 유사도만으로는 합치지 않는다.
- 후보를 작은 묶음으로 확인하고 중복 제거 후 부족하면 다음 후보를 계속 검사한다.
- 모델 로딩·다운로드·추론 실패는 경고를 남기고 기존 검사로 계속 진행한다. 그 실행은 의미 기반 중복 제거가 보장되지 않는 저하 상태다.
- GitHub Actions 모델 캐시를 추가하고 판정 점수·본문 비교 가능 건수를 stderr에 남긴다.
- `--dry-run`도 실제 본문·의미 검사를 수행한다. Telegram 발송과 Copilot 실무 참고 생성만 생략한다.

## 수집·분류·발송 재검토

- 정규 수집과 2일 보충 수집 모두 `select_candidates`를 거친다. 섹션별 선정과 기관 기사 우선 배치에서도 같은 전역 중복 기준을 사용한다.
- 선정한 결과로 준비 JSON을 만들고, 발송 단계는 해당 메시지를 그대로 읽는다. 재수집하거나 탈락한 기사를 다시 추가하지 않는다.
- 카테고리당 최대 5건, 총 최대 20건을 유지한다. 당일 후보를 소진하면 5건 미만일 수 있고, 기존 정책대로 3건 미만인 섹션만 2일 범위 보충 수집을 실행한다.
- 추가로 Telegram 수신 ID가 중복 설정되면 동일 메시지를 두 번 보내는 기존 문제를 재현했다. 공통 발송 함수에서 최초 순서대로 수신 ID를 중복 제거하도록 수정했고, 실패했던 회귀 테스트가 통과하는 것을 확인했다.
- `--prepared-input` 실제 CLI와 HTTP 전송 계층을 연결하되 MockTransport로 외부 발송을 차단해 검사했다. 중복 ID를 넣어도 각 수신처에 정확히 한 번, 저장된 내용 그대로 전달됐으며 재수집 호출은 없었다.

### 기존 잔여 사항

- 서로 다른 수신처/메시지 조각 중 일부 전송만 성공한 뒤 실패하면, 워크플로 전체 재시도에서 이미 전송된 부분이 다시 전달될 수 있다. HTTP 전송을 가로챈 재현에서 수신처 순서가 `1234,5678,1234,5678`이었다. 이번 한 번의 발송 내 수신 ID 중복 제거와 별개로, 실행 간 전송 체크포인트가 없는 기존 구조다.
- 전체 설치 환경 취약점 검사에는 기존 `aiohttp 3.14.1`과 `anyio 4.13.0`의 보고 항목이 남았다. 새로 추가한 FastEmbed/Pillow의 보고 항목은 해소했다. 따라서 환경 전체의 취약점이 0건이라고 주장하지 않는다.
- 최초 로컬 검토에서는 실제 Telegram 발송, cron-job.org 설정 변경, GitHub Actions 실행·배포를 하지 않았다. 이후 사용자 요청으로 발송 없는 GitHub Actions 미리보기를 실행했다. 결과는 별도 9/26 미리보기 보고서에 기록한다.

### 재검토 최종 판정

요구사항·코드 품질·보안·실행 QA·기존 정책 검토 5개 항목 모두 PASS. 이번 수정본의 차단 이슈는 해소했다. 최종 실시간 CLI는 고정 모델을 로드하고 의미 점수를 출력했으며, 카테고리별 4/2/5/4건을 선정했다. 후보 소진 시 최대 수량 미만으로 끝나는 기존 정책에 부합한다. 전체 284개 테스트와 52개 하위 테스트, 최종 집중 테스트 63개, strict 타입 검사, Ruff, lock 검사, 패키지 빌드를 통과했다.

Windows 한글 경로의 editable 설치 파일을 CP949로 읽는 기존 로컬 환경 문제가 있어, 검증은 `uv sync --locked --no-install-project`로 구성한 외부 가상환경과 `PYTHONPATH=src`로 실행했다. 운영 Linux Actions와는 별도 환경 문제다.

최초 검토 대상은 기준 커밋 `6cb82a4845891402232efd1b552c2c050a0f0ef3` 위의 미커밋 수정본이었다. 사용자 후속 승인에 따라 `codex/semantic-news-deduplication` 브랜치에 의미 중복 제거 `615b6fd`, 수신 ID 중복 방지 `a5c6f1f`를 커밋·푸시했다. 운영 main 병합과 Telegram 발송은 하지 않았다.
